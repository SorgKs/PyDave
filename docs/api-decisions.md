# API объектов — зафиксированные решения

Сессия уточнения API (ветка `game-engine-architecture-86710`).  
Связанные документы: `concept_refactor.md`, `engine/README.md`, `docs/api-open-questions.md`.

---

## 1. Модель объекта

**Решение:** объект — `dict`, логика — функции в `anims/`.

- Доступ к полям: `obj['x']`, `obj['vx']`, …
- Вызовы: `anims.behave(...)`, `anims.transform(...)`
- Не классы с методами (`obj.behave()`, `obj.x`)

---

## 2. Фабрика и владение структурой

**Решение:** единственная фабрика — `anims.create_object`.

- Реестр типов в `anims/` знает hitbox, якорь, слой, `init` / `behave` / `transform`
- `engine.objects` — только хелперы (`get_hitbox_rect`, `add_collision`, offsets), **без** своей фабрики
- Каноническая структура dict живёт в `anims`

---

## 3. `behave`

**Сигнатура (по смыслу):**

```text
behave(obj, keys, map)
```

| Аргумент     | Назначение                                      |
|--------------|-------------------------------------------------|
| `obj`        | объект-словарь                                  |
| `keys`       | снимок **действий** за кадр (не сырые клавиши)  |
| `map`        | карта проходимости (`surface_grid`)             |

**Формат `keys` (решение Q2 + уточнение):**

- семантический снимок действий за кадр; pygame снаружи (`main` / слой ввода мапит)
- каждая запись — **действие + модификатор**:
  - `+` — только что нажато (edge)
  - `=` — удерживается (level)
- примеры: `l+` / `l=` (влево), `r+` / `r=`, `j+` / `j=` (прыжок), `s+` / `s=` (выстрел), …
- представление: набор таких токенов за кадр (например `set`/`frozenset` строк, или dict с теми же ключами — при реализации достаточно любого membership-теста)
- `behave` / `anims` проверяют наличие токена (`'j+' in keys`), сырые scancode не видят
- врагам обычно пустой снимок

Канонические короткие коды действий (полный список: `l`,`r`,`j`,…) — зафиксировать при первой реализации игрока; схема `код+` / `код=` уже канон.

**Формат `map` и триггеры (решение Q3 + единицы):**

- `map` — `surface_grid` (клетки проходимости); отдельный пакет с `TS` **не нужен**
- **единицы `behave` и `physics` — тайлы, не пиксели**
  - `obj['x']`, `obj['y']`, `obj['vx']`, `obj['vy']`, `w`, `h`, offsets — в тайлах (или долях тайла)
  - индексы в `surface_grid` согласованы с этими координатами напрямую
  - `TS` (пиксели клетки) используется только при **рендере** / загрузке графики (`config` / `assets` / `render`)
- отдельный аргумент `triggers` **не передаём**
- при срабатывании триггер **записывается в объект**
- **формат записи триггера:** `название` + **доп. данные**, набор полей **индивидуален для каждого вида триггера**
  - общее: идентификация по имени (строка), плюс произвольный payload под этот триггер
  - не обязан совпадать со структурой физической `collisions` (object/static)
  - куда класть на obj (отдельный список vs общая очередь событий) — при реализации; смысл: событие на объекте, читает обычно `transform`
- реакция на сработавший триггер — через данные на `obj` (обычно в `transform`), а не через список в `behave`

**Формат физических `collisions`:**

- единой обязательной схемы (`normal`/`depth`/`point` для всех) **нет**
- у **каждого вида** коллизии — **свой набор** полей
- минимум — **факт** коллизии (идентификация вида: пол, стена, объект, …)
- доп. параметры пишутся **только где нужны** этому виду
- пример: коллизия с полом для отрисовки / `onG` — достаточно факта; penetration/normal — только если этот вид их использует
- триггеры по тому же принципу (имя + индивидуальный payload), но это отдельный класс событий от «физических» столкновений

**Права на запись:**

- **Нельзя** менять `obj['x']` / `obj['y']`
- **Можно** менять направление (`face`), скорость (`vx` / `vy`), прыжок (обычно через `vy`)

Координаты после `behave` пишет только физика.

## 4. `transform` и спрайты

**Сигнатура:**

```text
sprite_name = transform(obj)
```

**Когда вызывать:** каждый кадр, для каждого объекта.

**Входы (на объекте):**

- `obj['collisions']` — список коллизий после физики
- `obj['state']` — текущее состояние

**Поведение:**

- Читает коллизии / события на `obj` и `state`
- **Визуал:** смещение спрайта (`sprite_offset_*` и аналоги); возвращает имя спрайта в карте `assets`
- **Внутренние переменные объекта:** жизни, очки, патроны, таймеры, флаги состояния и т.п. (`obj['hp']`, `obj['score']`, `obj['ammo']`, …) — поля **конкретного** объекта, не глобальный `game_state`
- После обработки **удаляет / очищает** `obj['collisions']` (и аналогичные события кадра)

**Координаты и скорость (уточнение Q4 + knockback):**

- `x` / `y` — **только физика**
- `transform` **не** меняет `vx` / `vy`
- **отскок / knockback** при межобъектных столкновениях: **второй проход `physics`** (`resolve_object_collisions` и аналоги) применяет отскок там, где нужно
- `face` в `transform` допустим как визуал; не как замена физике
- зона `transform`: визуал + внутренние переменные объекта

**Спрайты (решения Q1 + загрузка):**

- у **каждого типа** в `anims/` — **`sprites_map()`** → **словарь** `{ключ_спрайта: имя_файла}`
- все файлы спрайтов лежат в **одной директории** (каталог спрайтов в `assets`)
- `assets` при старте:
  - загружает **все тайлы** сам
  - для объектов агрегирует `sprites_map()` всех типов, грузит файлы, строит карту **`ключ → surface`**
- обращение к спрайту **по ключу** словаря (не по имени файла)
- `transform` **возвращает ключ** из этой карты
- оффсет только в `obj`; в `obj` surface не пишется
- отдельная `get_sprite` **не нужна**
- `render`: `sprites[ключ]` (+ оффсет с `obj`)
- новый кадр анимации = файл в общей директории + запись в `sprites_map` типа; **`assets` не трогаем**
- ATLAS/crop в модуле типа для загрузки **не используются** (один спрайт = один файл)

## 5. Игровой цикл (целевой)

```text
# старт:
#   assets грузит все тайлы
#   assets спрашивает sprites_map() у каждого типа в anims → грузит спрайты → карта name → surface
#   парсер уровня: create_object + init → готовые объекты

для каждого obj:
    behave(obj, keys, map)        # map = surface_grid

physics.update_physics(objects)   # pass1: статика + pos; pass2: межобъектные + отскок;
                                  # сработавшие триггеры пишет в obj

для каждого obj:
    sprite_name = transform(obj)  # каждый кадр; чистит collisions / события
    # render использует sprites[sprite_name] и obj offsets
```

## 6. Краткая шпаргалка контрактов

| Функция     | Меняет pos? | Меняет vel? | Спрайт / оффсет / face (визуал) | Внутренние поля | collisions        |
|-------------|-------------|------------------|---------------------------------|-----------------|-------------------|
| `behave`    | нет         | да (намерение)   | нет*                            | по необходимости| не трогает        |
| `physics`   | да          | да (разрешение + отскок в pass2) | нет                      | нет             | заполняет         |
| `transform` | нет         | нет              | да (оффсет в `obj`; имя → return; face ок) | да     | читает и очищает  |

\* Смена `face` в `behave` — как часть намерения движения/ориентации; в `transform` — как визуал после коллизий.

## 7. Поля объекта (решение Q5)

**Общие для всех типов** (фабрика / базовый dict):

| Группа | Ключи |
|--------|--------|
| движение | `x`, `y`, `vx`, `vy` (**в тайлах**) |
| хитбокс / спрайт | `w`, `h`, offsets (`hitbox_offset_*`, `sprite_offset_*`, …) (**в тайлах**), `anchor_type` |
| прочее ядро | `state`, `face`, `onG`, `collisions`, `layer` |

**`layer`:** одно целое число — идентификатор слоя (не битовая маска).  
Правила «кто с кем» — таблица/логика в `physics` по этим числам, не через bitwise AND.

**Индивидуальные** (`hp`, `score`, `ammo`, таймеры, AI-поля и т.д.):

- не входят в общий минимум
- задаются в **индивидуальном `init`** типа в `anims/`

Значения `anchor_type`: канон `'ground'` / `'center'` — см. §13.

## 8. Парсер уровня и типы (решение Q6)

**Решение:** парсер уровня **сразу создаёт и инициализирует** объекты.

- Символ на карте (`Z`, `G`, `o`, …) переводится в канонический тип **внутри парсера**
- Парсер вызывает `anims.create_object(type, x, y, params)` (фабрика + индивидуальный `init`)
- Наружу отдаёт уже готовые объекты (или списки готовых obj), а не сырые `'z'`/`'g'`-плейсхолдеры
- `main` не мапит типы и не собирает врагов/предметы вручную из коротких кодов
- В рантайме имена типов только канонические: `dave`, `zombie`, `goblin`, `item_gem`, …

Короткие символы остаются только языком карты; после парсинга их нет.

---

## 9. `sprites_map` и загрузка ассетов

**Решение:** список/карта спрайтов принадлежит типу; `assets` только грузит файлы.

- `sprites_map()` → `dict[str, str]`: **ключ** (как обращаются в коде / что вернёт `transform`) → **имя файла** в общей директории спрайтов
- `assets` объединяет словари типов, грузит файлы → runtime-карта `ключ → surface`
- тайлы — зона `assets` (грузит все сам)
- смена набора кадров типа = правка `sprites_map` (+ файл на диске); код `assets` без изменений
- `init` к перечню файлов не относится

---

## 10. Гравитация и трение (решение Q7)

**Решение:** флаги живут на объекте; расчёт — только в `physics`.

- на obj: флаги вроде `has_gravity` / трение (точные имена — при реализации; задаются в `init` типа или фабрике)
- `engine.physics` читает флаги и применяет гравитацию / трение
- `behave` **не** интегрирует `x`/`y` и **не** дублирует гравитацию/трение
- враги без собственной «ручной» физики позиции

---

## 11. `compute_offsets` и отрисовка от якоря (Q8.1 + уточнение)

**Хитбокс:** offsets хитбокса считаются **один раз** при инициализации (`create_object`: `init` → `compute_offsets` по `w`/`h` и `anchor_type`).

**Спрайт / кадры:** каждый кадр **рисуется от якоря** объекта, не от заранее зафиксированного размера одного кадра:

- `'ground'` — якорь = **bottom-center**: низ середины кадра в `(x, y)`
- `'center'` — якорь = **центр** кадра в `(x, y)`

Размер текущего кадра (из `surface` по ключу `transform`) используется **в момент отрисовки** (или эквивалентно при подготовке кадра):  
`draw_pos` выводится из `(x, y)` + `anchor_type` + размер **этого** кадра.

Следствия:

- разные размеры кадров одного типа допустимы; якорь общий
- не нужно пересчитывать hitbox offsets каждый кадр
- хранить «навсегда» `sprite_offset_*` от одного эталонного кадра не обязательно — рендер опирается на якорь + текущий кадр
- `init` offsets хитбокса не обязан считать сам; однократный вызов hitbox-offsets — у фабрики

---

## 12. Сигнатура `init` (решение Q8.2)

```text
init(obj, params) -> None
```

- настраивает только индивидуальные поля объекта
- `params` — опциональный dict с карты/спавна (или `None`)
- **не** возвращает список спрайтов (это `sprites_map`)
- **не** обязан вызывать `compute_offsets` (это фабрика, один раз после `init`)

---

## 13. Значения `anchor_type` (решение Q8.3)

**Канон в `obj['anchor_type']`:** строки `'ground'` и `'center'`.

- `'ground'` — логическая точка (x, y) = середина низа (игрок, наземные)
- `'center'` — логическая точка = центр (летающие и т.п.)
- `engine` приводит свои имена к этому канону (алиас `'bottom_center'` → `'ground'` допустим только на входе хелперов, в obj не хранить)

---

## 14. `layer` (уточнение)

**Решение:** `obj['layer']` — **одно целое число** (категория слоя), **не** битовая маска.

- примеры значений задаёт реестр/`init` (player=1, enemy=2, … — конкретные константы при реализации)
- матрица столкновений / отталкивания в `physics` смотрит на пару чисел `(layer_a, layer_b)`
- битовые `LAYER_* = 0b…` в `engine` привести к int-категориям
