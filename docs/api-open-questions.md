## Q1. Как `transform` отдаёт спрайт рендеру?

Смещение уже решено: пишется в `obj`. Спрайт — нет.

Варианты:

1. Пишет `obj['sprite']` (или аналог), возврат `None` — рендер читает с объекта.
2. Возвращает имя спрайта; оффсет только в `obj`.
3. И пишет в `obj['sprite']`, и возвращает то же имя.

**Статус:** задан, ответа нет.

## Q2. Формат `keys` для `behave`

Что именно передаём как «кнопки»?

1. Семантический dict: `{left, right, jump, shoot, aim_up, …}` — `main` мапит pygame → семантика.
2. Сырые pygame: `pressed` (set) + `held` (key state).
3. Оба: семантика для игрока + raw при необходимости.

**Статус:** не задавался отдельно (упомянуто только «кнопки»).

## Q3. Формат `map` и `triggers`

Что такое `map` в `behave(obj, keys, triggers, map)`?

1. Только `surface_grid` (0/1/2) + `TS` / размеры.
2. Пакет: collision grid + ссылки на spikes / door / и т.д.
3. Read-only world-view: grid, объекты, декорации.

Что такое `triggers`?

1. Список объектов-триггеров из `all_objects`.
2. Отдельный список зон из парсера уровня.
3. То же, что зоны на `map` (отдельный аргумент не нужен?) — тогда зачем третий аргумент.

**Статус:** не уточнялось.

## Q4. Может ли `transform` менять `vx` / `vy` / `face`?

Сейчас зафиксировано: спрайт/оффсет, HP/очки/патроны, очистка collisions.  
Отскок / knockback при ударе — через скорость или только через физику на следующем кадре?

1. Да, `transform` может менять `vx`/`vy`/`face` (knockback, разворот).
2. Нет — только статус и визуал; knockback выставляет физика или следующий `behave`.

**Статус:** не задавался.

## Q5. Обязательные поля dict и имена ключей

Минимальный набор ключей объекта (кроме type-specific):

- позиция / скорость: `x`, `y`, `vx`, `vy`
- хитбокс / спрайт: `w`, `h`, `sprite_w`, `sprite_h`, offsets, `anchor_type`
- `state`, `face`, `onG`, `collisions`, `layer`
- статус: `hp`, `score`, `ammo` — у всех типов или только у игрока / по необходимости?

Якоря: строки `'ground'` / `'center'` (как в `anims`) или константы `engine` (`bottom_center` / `center`)?

**Статус:** не зафиксировано.

## Q6. Имена типов с карты vs реестр

`levels.py` сейчас отдаёт `'z'` / `'g'`, реестр — `'zombie'` / `'goblin'`.  
`item_gem` в `main` не зарегистрирован.

1. Парсер сразу пишет канонические имена (`zombie`, `goblin`, `gem`).
2. Таблица маппинга в `main` / `anims` (`'z' → 'zombie'`).

**Статус:** из анализа кода, в сессии API не решалось.

## Q7. Физика: трение и гравитация

Где применять гравитацию / трение?

1. Только в `engine.physics` (как в концепте).
2. Частично флаги на obj (`has_gravity`), физика читает флаги.

Behave не двигает pos — это уже решено. Нужно явно запретить врагам свою интеграцию в `behave` (сейчас zombie/goblin/ghost двигают `x`/`y`).

**Статус:** следует из решений, явного «да/нет» по гравитации в physics-only не было.
